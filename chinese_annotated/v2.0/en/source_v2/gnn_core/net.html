class HamGNN_v_2_0.models.HamGNN.net.HamGNNConvE3(config)[source]

Bases: BaseModel

HamGNN model based on E(3) equivariant graph convolutions.

This model learns representations of atoms and their interactions by stacking multiple equivariant convolutional layers. Each layer updates the features of atoms (nodes) and atomic pairs (edges) while strictly maintaining equivariance under rotation. The final output consists of equivariant features for nodes and edges, which are used for subsequent prediction of physical properties.

class HamGNN_v_2_0.models.HamGNN.net.HamGNNTransformer(config)[source]

Bases: BaseModel

HamGNN model based on E(3) equivariant Transformer.

This model uses an equivariant self-attention mechanism to capture interactions between atoms, replacing traditional convolution operations. It allows the model to dynamically weigh information from different neighbors when updating node features. The overall structure of the model is similar to HamGNNConvE3, but the core interaction layer is replaced with AttentionBlockE3.

class HamGNN_v_2_0.models.HamGNN.net.HamGNNPlusPlusOut(irreps_in_node=None, irreps_in_edge=None, nao_max=14, return_forces=False, create_graph=False, ham_type='openmx', ham_only=False, symmetrize=True, include_triplet=False, calculate_band_energy=False, num_k=8, k_path=None, band_num_control=None, soc_switch=True, nonlinearity_type='gate', export_reciprocal_values=False, add_H0=False, soc_basis='so3', spin_constrained=False, use_learned_weight=True, minMagneticMoment=0.5, collinear_spin=False, zero_point_shift=False, add_H_nonsoc=False, get_nonzero_mask_tensor=False)[source]

Bases: Module

Output module for HamGNN, used to construct the physical Hamiltonian and compute related properties.

This module receives equivariant features encoded by the graph neural network and uses them as coefficients to construct the complete Hamiltonian (H) and overlap matrix (S) via Clebsch-Gordan tensor products. It can handle basis sets from various DFT software (e.g., OpenMX, SIESTA, ABACUS), supports spin-orbit coupling (SOC), spin-constrained calculations, and can ultimately solve for the band structure.

Note

The implementation of this class is highly complex as it tightly couples physics (quantum chemistry, solid-state physics) with the mathematical principles of E(3) equivariant neural networks.

cal_band_energy_debug(Hon, Hoff, Son, Soff, data, export_reciprocal_values=False)[source]

Calculates the band structure (debug version).

Transforms the real-space Hamiltonian H(R) and overlap matrix S(R) to reciprocal-space H(k) and S(k) via Fourier transform, then solves the generalized eigenvalue problem H(k)c = ES(k)c to obtain the band structure.

Parameters:

  • Hon (torch.Tensor) – Predicted onsite Hamiltonian.

  • Hoff (torch.Tensor) – Predicted offsite Hamiltonian.

  • Son (torch.Tensor) – Predicted onsite overlap matrix.

  • Soff (torch.Tensor) – Predicted offsite overlap matrix.

  • data (Data) – Input data.

  • export_reciprocal_values (bool) – Whether to return reciprocal-space matrices.

Returns:

A tuple containing information such as band energy, wavefunctions, and band gap.

Return type:

tuple

cal_band_energy(Hon, Hoff, data, export_reciprocal_values=False)[source]

Calculates the band structure (official, non-debug version).

This function constructs k-point dependent Hamiltonians and overlap matrices for a batch of crystals from given onsite and offsite matrix blocks, then calculates the band structure by solving the generalized eigenvalue problem. The process is similar to cal_band_energy_debug but more streamlined, without dependency on pre-calculated Son and Soff.

Warning

The current implementation primarily targets openmx-type Hamiltonians.

Parameters:

  • Hon (torch.Tensor) – Onsite matrix blocks for all atoms/orbitals in the batch, typically with a shape of (N_nodes, nao_max*nao_max).

  • Hoff (torch.Tensor) – Offsite matrix blocks for all edges in the batch, typically with a shape of (N_edges, nao_max*nao_max).

  • data (Data) – PyG graph data object, containing atomic structure, k-points, and other information.

  • export_reciprocal_values (bool, optional) – If True, additionally returns the Hamiltonian HK, overlap matrix SK, derivative of SK dSK, and wavefunctions in reciprocal space. Defaults to False.

Returns:

If export_reciprocal_values is False, returns (band_energy, wavefunction, gap, H_sym). If export_reciprocal_values is True, returns (band_energy, wavefunction, HK, SK, dSK, gap).

Return type:

tuple

cal_band_energy_soc(Hsoc_on_real, Hsoc_on_imag, Hsoc_off_real, Hsoc_off_imag, data)[source]

Calculates the band structure including spin-orbit coupling (SOC).

This method constructs a 2x2 block matrix to represent the full SOC Hamiltonian from the given real and imaginary parts of the onsite and offsite SOC Hamiltonians. The diagonal blocks are the spin-conserving parts, and the off-diagonal blocks are the spin-flipping parts. The band structure is then obtained by solving the eigenvalue problem of this complex Hermitian matrix.

Warning

The current implementation primarily targets openmx-type Hamiltonians.

Parameters:

  • Hsoc_on_real (torch.Tensor) – Real part of the onsite SOC Hamiltonian.

  • Hsoc_on_imag (torch.Tensor) – Imaginary part of the onsite SOC Hamiltonian.

  • Hsoc_off_real (torch.Tensor) – Real part of the offsite SOC Hamiltonian.

  • Hsoc_off_imag (torch.Tensor) – Imaginary part of the offsite SOC Hamiltonian.

  • data (Data) – Input data, containing atomic structure, k-points, overlap matrix, etc.

Returns:

Returns a tuple containing the band energy band_energy and the flattened wavefunction wavefunction.

Return type:

tuple

This function ensures that only matrix elements between physically existing atomic orbitals have non-zero values, while those padding entries resulting from the use of a fixed size nao_max are set to zero.

reduce(coefficient)[source]

Decomposes matrix blocks into spherical harmonic coefficients (equivariant features) via Clebsch-Gordan decomposition.

This is the inverse process of matrix_merge. It approximately extracts feature components with a specific angular momentum l by averaging within orbital groups. This is mainly used for debugging or analysis purposes to check if the network has learned features that conform to physical symmetries.

Parameters:

coefficient (torch.Tensor) – Matrix blocks with a shape of (N, nao_max, nao_max).

Returns:

The resulting spherical harmonic coefficients from decomposition, reshaped to (N, nao_max*nao_max).
