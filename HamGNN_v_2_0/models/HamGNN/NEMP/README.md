# NEMP (Node Equivariant Message Passing) 架构

## 概述

NEMP（节点等变消息传递）是对HamGNN中原始EEMP（Edge Equivariant Message Passing）架构的优化实现。通过将部分计算复杂度从O(#edges)降低到O(#nodes)，提升了模型的训练速度，同时降低了GPU内存占用。

## 架构对比

### EEMP (原始ConvBlockE3架构)
- **核心机制**：在每条边上执行等变张量积(Tensor Product, TP)
- **计算复杂度**：O(#edges)，每条边都需要独立的TP操作
- **流程**：
  1. 对每条边：(src_node, dst_node) ⊗ edge_attrs → message
  2. 通过径向MLP生成权重调制消息
  3. 按目标节点聚合消息
- **特点**：保留了完整的几何信息，精度最高，但计算和内存开销大

### NEMP v1 (最小实现)
- **核心优化**：将边级TP转换为节点级TP
- **计算复杂度**：O(#nodes)
- **流程**：
  1. 径向MLP生成边系数EC (Edge Coefficients)
  2. EC逐维加权源节点特征
  3. scatter-sum到目标节点得"虚拟节点"
  4. 仅执行一次节点级TP：node ⊗ virtual_node
- **性能表现**：
  - 速度：显著提升
  - 内存：占用减半
  - 精度：Loss增大10倍（信息损失严重）
- **适用场景**：对速度要求极高，精度要求较低的场景

### NEMP v2 (方向环境分支)
- **改进点**：引入方向信息补偿机制
- **双分支架构**：
  - **标量分支**：与v1相同的EC加权机制
  - **方向分支**：edge_attrs经径向权重s(r)加权后聚合为node_env
- **融合策略**：两个分支分别做节点级TP后相加
- **性能表现**：
  - 速度：比EEMP快10%
  - 内存：占用为EEMP的50%
  - 精度：Loss仅略有增加（精度损失可接受）
- **适用场景**：需要平衡速度和精度的生产环境

### NEMP v3 (块级门控)
- **进一步优化**：
  1. **块级EC门控**：按irreps块而非全维度门控，减少O(E×D)操作
  2. **单次TP融合**：方向环境映射到节点空间后与标量分支融合，仅做一次TP
  3. **对称度归一化**：使用1/√(deg_src×deg_dst)稳定训练
  4. **可学习混合系数**：α和β参数动态平衡两个分支
- **性能表现**：
  - 速度：比EEMP快25%
  - 内存：与v2相当
  - 精度：Loss略有增加
- **适用场景**：对速度要求极高的推理场景

## 性能权衡分析

### 速度vs精度的根本原因

1. **信息完整性**：
   - EEMP在每条边做完整TP，保留了所有几何信息
   - NEMP通过预聚合减少TP次数，但损失了边级细粒度交互

2. **v2成功的关键**：
   - 方向环境分支补偿了标量聚合丢失的几何信息
   - 度归一化避免了聚合时的数值不稳定

3. **v3的极限优化**：
   - 块级操作进一步减少计算量
   - 单次TP避免重复计算
   - 但过度优化导致表达能力略有下降

## 技术细节

### 关键创新

1. **预聚合策略**：在执行昂贵的TP操作前，先在标量空间完成消息聚合
2. **方向信息保留**：通过额外的环境分支保留关键的几何信息
3. **块级操作**：利用irreps的块结构减少冗余计算
4. **自适应归一化**：根据节点度数动态调整聚合权重

### 数学原理

NEMP的核心思想是利用张量积的分配律：
```
∑_i (node_i ⊗ edge_attr_i) ≈ node ⊗ (∑_i weighted_edge_attr_i)
```

通过巧妙的权重设计和多分支架构，在保持等变性的同时降低计算复杂度。
